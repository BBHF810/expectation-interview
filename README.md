# 相互期待感AIインタビュー (工大祭展示向けWebアプリ)

家族や友人など身近な人に対して抱いた「期待」と、「実際に起きた出来事」を、AIインタビュアーとの対話を通して振り返る体験型Webアプリケーションです。

---

## 1. 展示の目的とコンセプト
来場者が身近な人に対して抱いた期待と、実際に起きたことを本人の言葉で振り返る体験を提供します。

- 誰に、何を期待したか
- 実際にはどうなったか
- 期待どおりだった、またはすれ違った具体的な出来事
- そのとき本人がどのように受け止めたか

> **【重要なお知らせ】**
> 本アプリは医療、心理診断、性格診断、相性診断を行うものではありません。
> 回答者や相手の性格、心理、関係性を評価・断定・採点することは一切ありません。

---

## 2. 主な機能
- **開始前ガイダンス・同意取得**: AI利用、外部送信、個人情報の不入力、非保存、診断ではないことの明示と同意チェック
- **事前ステップ選択**:
  - 年齢層選択（10歳以下向けには、ひらがな主体のやさしい言葉遣いへ切り替え＆保護者・スタッフ同伴案内）
  - 話す相手の選択（お父さん・お母さん、子ども、パートナー、友だち、その他＋自由記述）
  - 介護に関する出来事の確認
  - 期待と結果の認識選択（具体例つきで「期待どおりだった」「すれちがった」「どちらともいえない」を選択）
- **一人で体験するモード（最大3問制御）**:
  - 年齢層別最適化（介護確認は31歳以上のみ、親・子・兄弟を「家族」に集約）
  - 1画面1問表示のステップ式UI
  - ユーザーの回答に応じたリアルタイムGemini動的質問の生成
  - 最大3問で確実に終了する対話制御
  - 「思いつかない」「答えたくない」「体験を終了する」「最初からやり直す」ボタン
  - 音声入力（Web Speech API）および手動テキスト修正のシームレスな併用
  - 表情・状態（話す/聴く/考える/待機）が変化するアニメーションアバター
  - 中立的な振り返りと、展示用エンタメ動物診断カードの提示
- **ふたりで体験するモード（交互インタビュー）**:
  - 二人の名前と関係性（友人・カップル・夫婦・家族等）の登録
  - 二人それぞれの視点で「相手への期待と結果」を事前選択
  - 参加者Aと参加者Bが交互に答えるターン制インタビュー（各回答に応じたAI動的質問生成）
  - 二人の視点の整理・比較と、二人の関係性に寄り添うペア動物診断カードの提示
- **「相互期待感の一致・不一致」具体例解説**:
  - 「💡 相互期待感とは？ 具体例を見る」ボタン＆モーダル
  - 友人・家族・介護など、身近な一致・不一致のエピソード例を図解
  - ウェルカム画面やインタビュー中いつでも確認可能
- **エピソードデータ収集・ローカル保存・エクスポート**:
  - 体験完了時に、セッションデータ（属性、期待タイプ、各回答全文、振り返り）を端末ローカル（`localStorage`）に自動蓄積
  - スタッフ・研究用管理パネル（リアルタイム集計、詳細閲覧）
  - **📥 CSVダウンロード**（Excel用UTF-8 BOM付き）および **📥 JSONダウンロード**
- **安全対応（センシティブな内容の検知）**:
  - 自傷・深刻な暴力・虐待等の兆候を検知した場合、インタビューを即座に停止し、身近な大人やスタッフへの相談を案内
- **堅牢なフォールバック機構**:
  - API未設定、タイムアウト、レート制限、ネットワーク障害時でも、事前選択に応じた固定質問・固定振り返りで体験を継続可能

## 3. 技術構成
- **フロントエンド / バックエンド**: Next.js 15 (App Router), React 19, TypeScript
- **スタイル**: CSS Modules / Global CSS（展示向けに最適化された清潔感のあるUI、タップ領域44px以上、本文16px以上、フォーカスリング完備）
- **AI SDK**: Google Gen AI 公式SDK (`@google/genai`)
- **スキーマ検証**: Zod (リクエスト、レスポンス、Gemini構造化出力の厳密バリデーション)
- **テスト**: Vitest, @testing-library/react, jsdom
- **ホスティング**: Vercel

---

## 4. プライバシー保護とデータ管理
- **セッション中のみ保持**: 回答データはクライアントのReactステート（メモリ内）にのみ一時保持され、ブラウザの `localStorage`、`Cookie`、サーバーサイドのデータベースには一切保存されません。
- **ログへの非出力**: サーバーログ（Vercelログ等）に利用者の回答本文、個人情報、プロンプトは一切出力されません。記録されるのはリクエストID、所要時間、モデル名、フォールバック有無等の運用メトリクスのみです。
- **ページ再読み込み・リセット**: 「最初からやり直す」またはページ再読み込みで、すべての入力内容が完全に破棄されます。

## 5. API料金・コストを抑える仕組み
展示ブースでの想定外の課金を防ぐため、以下の制御を実装しています：
1. **最大質問数の制限**: 1セッションにつき質問生成は最大3回、振り返り生成は1回のみに厳格制限。
2. **文字数制限**: 入力欄およびサーバーサイドで各回答を最大500文字に制限。
3. **最小限のコンテキスト**: Geminiへ送信する過去履歴を最小限に圧縮。
4. **トークン数・Temperature制限**: `maxOutputTokens` を質問生成時150、振り返り時300に制限。低温度（0.2）でブレを防止。
5. **二重送信防止**: API通信中は送信ボタンを `disabled` 化し、重複リクエストを抑止。
6. **タイムアウトとフォールバック**: 7〜8秒のタイムアウトを設定し、無駄な長時間接続を防止。
7. **Google Cloud側の予算管理**: Google Cloud Console / Google AI Studio 側でもプロジェクトの月間予算アラートおよび利用上限（Quota limits）を設定することを推奨します。

## 6. 環境変数
プロジェクトルートの `.env.local` または Vercel の環境変数に以下を設定します。
（`.env.example` を参考に設定してください。APIキーはリポジトリにコミットしないでください）

| 環境変数名 | 必須 | デフォルト値 | 説明 |
| :--- | :---: | :--- | :--- |
| `GEMINI_API_KEY` | 推奨 | (なし) | Google AI Studioで取得したAPIキー。未設定の場合は自動で固定質問・振り返りフォールバックが動作します。 |
| `GEMINI_MODEL` | 任意 | `gemini-3.5-flash-lite` | 使用するGeminiモデル。安定版Flash-LiteまたはFlashモデルを指定します。 |
| `GEMINI_MAX_OUTPUT_TOKENS` | 任意 | `200` | 生成AIの最大出力トークン数 |
| `GEMINI_TEMPERATURE` | 任意 | `0.2` | 生成AIの温度パラメータ（0.0〜1.0） |

### モデルの変更方法
コードの修正は不要です。環境変数 `GEMINI_MODEL` の値を変更するだけで、使用モデルを切り替えることができます（例: `gemini-2.5-flash`, `gemini-3.5-flash-lite` 等）。

## 7. ローカル起動方法

### 前提条件
- Node.js v20+ / v24+
- npm v10+

### 手順
```powershell
# 依存関係のインストール（完了済み）
npm install

# 開発サーバーの起動
npm run dev
```
ブラウザで [http://localhost:3000](http://localhost:3000) を開きます。

## 10. 制限事項・運用上の注意
- **データベース保存なし**: 来場者の回答データはデータベースに一切蓄積・保存されません。展示用端末の画面を再読み込みするか「最初からやり直す」を押すとデータは即時消去されます。
- **診断機能の主目的化防止**: 性格診断や動物診断は展示を盛り上げるための親しみやすいエンタメ演出（広告用）であり、学術的・医療的な性格プロファイリングや相性判定を行うものではありません。
- **音声入力の環境依存**: 音声入力はブラウザの Web Speech API を利用しています。周囲の騒音が大きい展示会場では、必要に応じてキーボード入力による修正を行ってください。
